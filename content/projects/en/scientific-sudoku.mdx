## The Problem

Traditional Sudoku generators and solvers in the browser are usually implemented in pure JavaScript, which leads to inconsistent solving times when facing high-difficulty grids (17 clues or less). Simple backtracking heuristics become slow because JS cannot optimize contiguous memory access or deep recursion at the metal level.

The challenge was to design a solver that runs in real-time in the browser, maintaining 60 FPS in the UI, without relying on an external server for heavy computation.

## Architectural Decisions

1. **Rust + WASM Solving Engine:** An optimized backtracking solver using constraint propagation and MRV (Minimum Remaining Values) heuristics was implemented. By compiling to WASM, the engine runs at native speed within the browser, eliminating network latency and allowing high-difficulty grids to be solved in milliseconds.

2. **Reactive UI with Svelte 5:** The interface needed to reflect cell changes without complete re-renders. Svelte 5 allowed surgical DOM updates with a minimal bundle size, maintaining a fluid experience even during step-by-step solver animations.

3. **Decoupled Architecture:** The WASM engine communicates with the UI via a shared type contract, allowing the solver implementation to be swapped without modifying the interface.

## The Algorithmic Core

The solving engine implements backtracking with constraint propagation. Instead of checking numbers at random, it evaluates cells with the fewest valid options first, drastically pruning the search tree.

```rust
pub struct SudokuEngine {
    grid: [[u8; 9]; 9],
    steps: Vec<(usize, usize, u8)>,
}

impl SudokuEngine {
    pub fn solve(&mut self) -> bool {
        let mut empty = (9, 9);
        let mut min_options = 10;

        for row in 0..9 {
            for col in 0..9 {
                if self.grid[row][col] == 0 {
                    let count = self.count_options(row, col);
                    if count < min_options {
                        min_options = count;
                        empty = (row, col);
                    }
                }
            }
        }

        if min_options == 10 {
            return true;
        }

        let (row, col) = empty;
        for num in self.get_candidates(row, col) {
            self.grid[row][col] = num;
            self.steps.push((row, col, num));
            if self.solve() {
                return true;
            }
            self.grid[row][col] = 0;
            self.steps.pop();
        }

        false
    }
}
```

## Trade-offs

| Approach | Advantages | Disadvantages / Costs |
| :--- | :--- | :--- |
| **WASM vs Pure JS** | Native speed, no GC pauses | Higher build pipeline complexity |
| **Optimized Backtracking vs Brute Force** | Predictable solving even for extreme grids | More complex code than a naive solution |
| **Svelte 5 vs React** | Minimal bundle, reactivity without virtual DOM | Smaller third-party ecosystem |

## Impact

The result is a solver that processes extreme grids in less than 50ms, with an interface that animates the step-by-step solving process at 60 FPS. The compiled WASM bundle is 18KB, and the entire app loads in less than 2 seconds even on slow connections.

The project demonstrates mastery in three key areas: combinatorial optimization algorithms, cross-compiling to WebAssembly, and designing reactive interfaces that explain technical complexity clearly.
