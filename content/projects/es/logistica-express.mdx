## El Problema de Negocio

La gestión de inventarios en operaciones logísticas críticas suele enfrentar un cuello de botella letal: las condiciones de carrera (race conditions) al actualizar el stock en tiempo real desde múltiples nodos. Un dashboard tradicional basado en peticiones CRUD estándar no garantiza la integridad transaccional cuando decenas de operadores descuentan inventario de forma simultánea.

Se requería un sistema capaz de manejar la concurrencia absoluta sin bloquear la base de datos entera, asegurando que las operaciones de almacén en puntos estratégicos, como San Javier o los nodos del Maule, mantuvieran una sincronización perfecta.

## Decisiones Arquitectónicas

Para resolver este desafío, diseñé una arquitectura orientada al rendimiento extremo y la seguridad de memoria:

1. **Core Engine en Rust:** Se descartaron lenguajes con Garbage Collector (como Node.js o Python) para el núcleo transaccional. Rust permitió implementar un control de stock atómico real mediante locks granulares a nivel de fila y estructuras de datos seguras en concurrencia, garantizando latencias predecibles.
2. **Frontend Reactivo con Svelte 5:** El dashboard de los operadores requería actualizar la información en pantalla sin recargar el DOM completo ni saturar el cliente. Svelte 5 permitió una reactividad quirúrgica y un bundle final minúsculo.
3. **Contenerización con Docker:** Todo el sistema se empaquetó en contenedores Docker independientes, separando el motor de base de datos, el backend de Rust y el cliente servido estáticamente, facilitando un despliegue sin fricciones en cualquier infraestructura.

## Trade-offs (Decisiones de Diseño)

| Enfoque | Ventajas | Desventajas / Costos |
| :--- | :--- | :--- |
| **Control Atómico en Rust** | Cero riesgo de sobreventa (overselling). Rendimiento extremo. | Curva de desarrollo inicial más lenta por el *Borrow Checker*. |
| **Svelte 5 vs React** | Menor uso de memoria en el cliente; reactividad más natural. | Ecosistema de librerías de terceros ligeramente menor. |
| **Microservicios vs Monolito Dockerizado** | Alta cohesión. Despliegue simple y replicable. | El escalado se hace por bloque, aunque para este volumen es óptimo. |
